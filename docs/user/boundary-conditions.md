# Boundary Conditions

Boundary conditions (BCs) in Q2D are specified through two
complementary mechanisms:

1. **`input.ini` sections** — high-level, named BC definitions via
   `[BCB-Block*]`; used for simple cases and verified against the
   grid automatically.
2. **`INPUT/bc.txt`** — low-level, face-by-face data table that
   defines the type and parameters of each BC for every block face
   cell; generated by the ATLAS pre-processor for complex multi-block
   meshes.

The two approaches ultimately produce the same internal
representation. For simple cases the `input.ini` approach is
sufficient; for complex multi-block cases the `bc.txt` file is
generated once by ATLAS and shipped with the case.

!!! info "BC files and ATLAS"
    In the normal Hydra workflow, the BC file is generated by the
    **ATLAS** pre-processor. ATLAS takes a mesh, a prescribed BC
    state, and the thermodynamic data as inputs and writes the BC
    file in the format Q2D expects. If ATLAS is not available, the
    BC file can be prepared manually as long as it conforms to the
    expected format (see below).

!!! note "Q2D BC code set"

    Q2D adopts the MOSE-compliant BC code set (`101`, `103`, `200`,
    `300`, `301-304`, `400`, `401-407`, `410`, `420`, `501`, `502`).
    A migration helper can easily convert legacy Q2D BC codes (1..1000 range)
    into the current code set.

## Multi-grid Naming Convention

When multigrid is enabled, one BC file per grid level is required:

| File | Level |
|------|-------|
| `INPUT/bc_x1.txt` | Finest grid |
| `INPUT/bc_x2.txt` | 2× coarser |
| `INPUT/bc_x4.txt` | 4× coarser |
| `INPUT/bc_x8.txt` | 8× coarser |

For single-grid cases the file is simply `INPUT/bc.txt`.

## Face Numbering

For a 2D block with $n_i \times n_j$ cells the **four** faces are
labelled (there are no top/bottom $k$-faces in Q2D):

| Face index | Location | Varying indices |
|:----------:|----------|-----------------|
| 1 | $i = 1$ (imin) | $j = 1 \ldots n_j$ |
| 2 | $i = n_i$ (imax) | $j = 1 \ldots n_j$ |
| 3 | $j = 1$ (jmin) | $i = 1 \ldots n_i$ |
| 4 | $j = n_j$ (jmax) | $i = 1 \ldots n_i$ |

In `bc.txt` records the legacy `k`-coordinate column is preserved for
format compatibility with MOSE-form readers but always carries
`k = 1`. The `bc.txt` reader transparently accepts both 5-field
(legacy Q2D) and 6-field (MOSE-form) record widths via
`detect_record_width`.

## `input.ini` — High-Level BC Setup

### Block–Face Assignment

Use `[BCB-Block{m}]` sections (one per block) to assign a named BC to
each face:

```ini
[BCB-Block1]
face1 = inflow
face2 = outflow
face3 = wall
face4 = symmetry
```

Each value is the name of a section (defined elsewhere in
`input.ini`) that holds the BC parameters.

The wildcard `[BCB-Block*]` applies the same assignment to every
block:

```ini
[BCB-Block*]
face1 = inlet
face2 = extrapolation
face3 = symmetry
face4 = extrapolation
```

### Named BC Sections

Each referenced name becomes a section that carries the BC type and
its parameters. The `type` key determines the BC behaviour:

**Null / unused face:**

```ini
[null]
type = 0
```

**Symmetry / slip wall:**

```ini
[symmetry]
type = 3
```

**Extrapolation (supersonic exit):**

```ini
[extrapolation]
type = 11
```

**Inflow / outflow (ambient, subsonic):**

Prescribes stagnation or static conditions; the solver determines
inflow/outflow from the local Mach number.

```ini
[ambient]
type  = 4
p0    = 1.02828e5   ; total pressure [Pa]
T0    = 300.0       ; total temperature [K]
p     = 0.97250e5   ; back pressure [Pa]  (for outflow)
```

For a mass-flux driven inlet:

```ini
[inflow]
type = 4
g    = 80.648       ; mass flux [kg/(m²·s)]
T    = 300.0        ; static temperature [K]
```

For turbulent flows, add turbulence variables:

```ini
[inflow]
type  = 4
g     = 59.29
T     = 555.0
kappa = 2.25e-3
omega = 6250.0
```

**Supersonic inlet:**

Prescribes Mach number, static pressure and temperature at a
supersonic inflow face.

```ini
[inlet]
type  = inlet
mach  = 4.0
p     = 1.0e5
T     = 300.0
alpha = 0.0         ; flow angle in x-y plane [deg]
```

Alternatively, stagnation conditions:

```ini
[inlet]
type = inlet
p0   = 10.342e5
T0   = 555.56
```

**Viscous wall — adiabatic (zero heat flux):**

```ini
[wall]
type = 5
q    = 0.0          ; heat flux [W/m²]
```

**Viscous wall — isothermal:**

```ini
[wall]
type = 6
T    = 300.0        ; wall temperature [K]
```

**Piecewise wall (symmetry + viscous):**

When the wall face spans both a symmetry plane and a no-slip surface,
the `direction` key splits the face into patches by coordinate range:

```ini
[wall]
direction = x
patch1    = symmetry
range1    = -1.0  0.0
patch2    = adiabatic
range2    = 0.0   2.0

[symmetry]
type = 3

[adiabatic]
type = 5
q    = 0.0
```

**Block-to-block connection:**

```ini
[BCB-Block1]
face4 = connection

[connection]
type = connection
```

For the connection to work, the matching faces of the two blocks must
have compatible dimensions. The ATLAS pre-processor generates the
full mapping data in `bc.txt`.

## `bc.txt` — Low-Level Face Data

`INPUT/bc.txt` is the raw, face-by-face boundary condition file read
directly by the solver. It is the ground truth from which the solver
builds its BC data structures.

The file is structured as a list of information for every boundary
cell.

The format is as follows:

```
<block>  <i>  <j>  <k>  <face>  <type>
<data line (if required by type)>
```

**Line 1 — face identifier:**

| Field | Description |
|-------|-------------|
| `block` | 1-based block index |
| `i`, `j`, `k` | Cell indices of the boundary cell (1-based) — `k` always equals 1 in Q2D |
| `face` | Face index of that cell (1–4 in Q2D, see [Face Numbering](#face-numbering)) |
| `type` | Numeric BC type code (see table below) |

All boundary cells are listed — one entry per face cell, face by
face, block by block.

**Line 2 — BC data (type-dependent):**

Some BC types carry additional data on the second line (see [BC
Types](#bc-types)). For types that carry no data (symmetry,
extrapolation, axisymmetry), the second line is **absent**.

The Q2D reader auto-detects the line-1 record width (5 vs 6 fields)
via `IO_BC::detect_record_width` and accepts both legacy Q2D and
MOSE-form files transparently.

## BC Types

The following table lists all numeric BC type codes used in `bc.txt`,
their physical meaning, and the format of the required data line.

!!! info "BC types and ATLAS"
    More details on these BC types and their parameters can be found
    in the ATLAS documentation, which defines the expected format
    and semantics of the BC file. The above table serves as a
    reference for users preparing BC files manually or interpreting
    the output from ATLAS.

### Connection

| Type | Name | Data line (comma-separated) |
|:----:|------|-----------------------------|
| `0` | Null / unused | — |
| `101` | Block connection | `bs  is  js  ks  fs  d11  d12  d21  d22` |
| `102` | Chimera overset | `n1  n2` then `n1+n2` donor lines: `bD iD jD kD  vol_frac` |
| `103` | Coupled wall | `bs  is  js  ks  fs  d11  d12  d21  d22` |

`d11, d12, d21, d22` are the $2 \times 2$ index-direction cosine
matrix mapping source to target indices.

### Euler Boundaries

| Type | Name | Data line |
|:----:|------|-----------|
| `200` | Axisymmetry | — |
| `300` | Symmetry / slip wall | — |
| `400` | Extrapolation (supersonic exit) | — |

### Inlet / Outlet

| Type | Name | Data line (comma-separated) |
|:----:|------|-----------------------------|
| `401` | Inlet — stagnation ($T_0$, $p_0$) | `T0,  p0,  alpha,  beta,  rel_fac,  [massf_1 … massf_ns],  [turb_vars]` |
| `402` | Inlet — time-varying $p_0(t)$ | `T0,  p0_file,  alpha,  beta,  rel_fac,  [massf],  [turb]` |
| `403` | Inlet — mass flux + $T_0$ | `T0,  g,  alpha,  beta,  rel_fac,  [massf],  [turb]` |
| `404` | Inlet — mass flux + $T$ static | `T,   g,  alpha,  beta,  rel_fac,  [massf],  [turb]` |
| `405` | Supersonic inlet ($M$, $T$, $p$) | `mach,  T,  p,  alpha,  beta,  rel_fac,  [massf],  [turb]` |
| `406` | Outlet — back pressure | `p_back,  rel_fac` |
| `407` | Ambient ($T_0$, $p_0$, $p_\text{back}$) | `T0,  p0,  p_back,  alpha,  beta,  rel_fac,  [massf],  [turb]` |
| `410` | Assigned state (time-varying file) | `filename  [periodic]` |
| `420` | Choked nozzle | `mach_dummy,  T0,  p0,  p_sub,  p_sup,  r_throat,  rel_fac,  [massf],  [turb]` |

!!! info "Borda-flow choked nozzle (BC 420)"

    BC 420 in Q2D supports two operating modes selected via the
    `mach_dummy` sentinel field on the second `bc.txt` line:

    - **Standard mode** (`mach_dummy ≥ 0`) — classical
      Riemann-invariant treatment.
    - **Borda-flow mode** (`mach_dummy = -20`) — applies the
      Glaister 1988 generalised Riemann invariant with full velocity
      magnitude $H_0$ following Fievisohn 2016/2017. Used for
      choked-nozzle inflow conditions in hybrid rocket motors and
      rotating-detonation engines.

    Implementation: `Lib_BC_Fluxes_Inflow_Nozzle.f90`.

**Common fields:**

| Field | Description |
|-------|-------------|
| `alpha` | In-plane flow angle [rad] or the token `normal` (face-normal inflow) |
| `beta` | Out-of-plane flow angle [rad] or `normal` (kept for format parity; ignored in 2D) |
| `rel_fac` | Relaxation factor (0–1; use 1.0 for no relaxation) |
| `massf_s` | Mass fraction of species $s$ (multi-species only; one value per species) |
| `turb_vars` | Turbulence quantities ($k$, $\omega$ or $k$, $\varepsilon$) |

!!! note "Outflow under-relaxation (BC 406)"

    The Q2D `Outflow` kernel applies an under-relaxation to the exit
    pressure:
    `Face_Prim(np) = p_exit * BC_rel_fac + Bound_Prim(np) * (1 - BC_rel_fac)`,
    where `BC_rel_fac` is the relaxation factor (use `1.0` for direct
    assignment of `p_exit`).

### Viscous Walls

| Type | Name | Data line (comma-separated) |
|:----:|------|-----------------------------|
| `301` | Adiabatic / prescribed heat flux | `q_wall,  k_rough,  eps_wall` |
| `302` | Isothermal wall | `T_wall,  k_rough,  eps_wall` |
| `303` | Wall melting (paraffin/HTPB grain) | `T_wall_init,  Lv,  rho_solid,  c_solid,  k_rough,  [GSI parameters]` |
| `304` | Wall pyrolysis (HDPE/PP/Carbon) | `T_wall_init,  Ea,  A_pre,  rho_solid,  k_rough` |

| Field | Description |
|-------|-------------|
| `q_wall` | Wall heat flux [W/m²] (positive = into fluid; set to `0.0` for adiabatic) |
| `T_wall` | Wall temperature [K] |
| `Lv` | Latent heat of melting/vaporisation [J/kg] |
| `Ea`, `A_pre` | Pyrolysis Arrhenius parameters (activation energy [J/mol], pre-exponential factor) |
| `k_rough` | Sand-grain roughness height $k_s$ [m] (`0.0` for smooth wall) |
| `eps_wall` | Wall emissivity (0–1) |

!!! info "Wall melting / `GSI_Paraffin` (BC 303)"

    BC 303 in Q2D dispatches to one of two surface-kinetics models:

    - **`GSI_Melting`** — the default wall-melting model
      (`y_SEBS = 0`, `cracking = .false.`).
    - **`GSI_Paraffin`** — a paraffin-grain surface-kinetics model
      with two additional features over plain wall-melting:
        1. **SEBS-aware solid properties**: includes the `y_SEBS`
           contribution to `cp_solid` and `Dh_melting`, completing the
           fusion-energy balance when a paraffin–SEBS blend is used.
        2. **Wall-instantaneous cracking branch** (activated by
           `cracking = .true.`): C32H66 → 16 C2H4 + H2 collapsed at
           the wall surface. The same stoichiometry is also available
           as a gas-phase mechanism (`Singh_WC32` in FLINT); the
           wall-instantaneous form is robust on coarse grids and stiff
           Strang regimes.

    GSI material properties (including `y_SEBS` and the `cracking`
    switch) are currently hardcoded as module-level defaults in
    `Q2D_Lib_GSI` — there is no INI section for them yet; moving them
    to the configuration registry is an open TODO
    (`Register_Physics.f90`).  With the default settings
    (`y_SEBS = 0`, `cracking = .false.`), `GSI_Paraffin`
    reduces to `GSI_Melting`.

    See [Finite-Rate Kinetics — Surface Kinetics](../theory/kinetics.md#surface-kinetics-paraffin-grain-model)
    for the full physics.

### Physical Models

| Type | Name | Data line |
|:----:|------|-----------|
| `501` | Manifold connection | `bs  fs` |
| `502` | SRM grain boundary | `T_af,  a,  n,  p_ref,  rho_grain,  SF_geo,  [massf_1 … massf_ns]` |

!!! tip
    More details on these BC may be found in the [Theory Guide](../theory/index.md)

## Examples

**1-D Case (100 cells, all faces extrapolation)**

```
       1       1       1       1       1     400
       1     100       1       1       2     400
       1       1       1       1       3     400
       1       2       1       1       3     400
...
       1     100       1       1       4     400
```

Faces 1 and 2 each have 1 entry (the single cell at the end of the
1-D domain). Faces 3 and 4 each have 100 entries (one per $i$-cell).

**2-D Supersonic Inlet (type 405)**

```
       1       1       1       1       1     405
    0.300000E+01,    0.100000E+01,    0.100000E+01,         normal,         normal,    0.100000E+01,    0.100000E+01,
       1       1       2       1       1     405
    0.300000E+01,    0.100000E+01,    0.100000E+01,         normal,         normal,    0.100000E+01,    0.100000E+01,
```

**Block Connection (type 101)**

```
       1       1      16       1       4     101
       2       1       1       1       3       1       0       0       1
```

The data line carries the target block and face information plus the
direction cosines.

**Viscous Inflow (type 401)**

```
       1       1       1       1       1     401
    0.300000E+03,    0.972500E+05,    0.000000E+00,         normal,    0.100000E+01,    0.100000E+01,   0.10000E+01,
```

## Complete `input.ini` Example

Below is a complete example for a 2-D Navier–Stokes flat-plate case
(single block):

```ini
[Q2D-Parameters]
iter-threshold = 100000

[Q2D-Physics]
equations = navier-stokes

[Q2D-Numerics]
cfl                   = 0.5
riemann-solver        = HLLC
flux-limiter          = vanleer
space-reconstruction  = MUSCL
integration-variables = cons
time-scheme           = RK2
time-accurate         = false
irs-beta              = 0.0
OMP-parallel          = do          ; 'do' (default) or 'task'

[Q2D-IO]
sol-diter   = 1000
shell-diter = 100

;--- Gas model -----------------------------------------------------------------
[GPB-Phase1]
type    = ideal-gas
species = air
gamma   = 1.4
R       = 287.0
mil     = 1.79e-5
Pr      = 0.72

;--- Initial condition ---------------------------------------------------------
[ICB-Block1]
type  = homogeneous
p     = 97250.0
T     = 300.0
mach  = 0.2

;--- Boundary conditions -------------------------------------------------------
[BCB-Block1]
face1 = ambient
face2 = ambient
face3 = inflow
face4 = wall

[ambient]
type = 4
p0   = 97250.0
p    = 97250.0
T0   = 300.0

[inflow]
type = 4
g    = 80.648
T    = 300.0

[wall]
direction = x
patch1    = symmetry
range1    = -1.0 0.0
patch2    = adiabatic
range2    = 0.0  2.0

[symmetry]
type = 3

[adiabatic]
type = 5
q    = 0.0
```
